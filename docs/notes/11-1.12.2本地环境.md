## 2. 版本组合

| 组件 | 版本 |
|---|---|
| Minecraft | 1.12.2 |
| Forge（运行时） | **14.23.5.2859** |
| Forge（编译时） | 14.23.5.2768 |
| IE | 0.12-98 |
| Java | 8（`D:\dev\tools\jdk-8`） |

> **为什么编译和运行时 Forge 版本不同**：
> 1.12.2 的 Forge maven 上 **2859 没有 userdev 包**（404），而 ForgeGradle 2.3 编译必须用 userdev；
> 2768 有 userdev。但 IE 0.12-98 要求运行时 ≥ 14.23.5.2838，所以运行时单独用 2859 的 universal。

## 4. 首次搭建踩到的坑（都已绕过）

| 坑 | 现象 | 解法 |
|---|---|---|
| BMCLAPI 把通用库重定向到已关闭的 USTC 镜像 | `diff4j` / `jAstyle` 下载失败 | 通用库走 Maven Central |
| Gradle 4.9 不支持 `content {}` | 配置阶段报错 | 只用仓库顺序 |
| `deobfCompile files(...)` 被拒 | "Only allowed to use maven dependencies" | 建本地 Maven 仓库 `repo/`，用坐标 |
| `setUnlocalizedName` 找不到 | MCP stable_39 改名 | 改用 `setTranslationKey` |
| `IInventory.isEmpty()` 抽象 | 编译失败 | 显式实现 |
| `IWorldNameable.getDisplayName()` 抽象 | 编译失败 | 补 `getName/hasCustomName/getDisplayName` |
| 2859 的 userdev 404 | FG 解析失败 | 编译用 2768 |
| fastutil 从官方 maven 下载挂起 | `compileJava` 卡住 | 手动从 BMCLAPI 下载放入缓存 |
| BMCLAPI 对部分 Forge 制品 403 | universal/vecmath/trove4j | 官方 + `libraries.minecraft.net` 兜底 |
| 2859 的 installer 不存在 | 404 | 用 `install_profile.versionInfo` + 手动换 universal |
| classpath 同时有 2768/2859 universal | IE 报"Forge 14.23.5.2768" | 删掉 2768 的 universal |
