## 2. 各版本"工具/装备 addon"的关键差异

| 关注点 | 1.12.2 | 1.16.5 | 1.20.1+ |
|---|---|---|---|
| 物品类 | `Item` + `setUnlocalizedName` | `Item` + `Properties` | `Item` + `Properties` |
| 注册 | `RegistryEvent.Register<Item>` | `DeferredRegister` | `DeferredRegister.Items` |
| NBT | `NBTTagCompound` | `CompoundTag` | `CompoundTag` |
| 能量获取 | `CapabilityEnergy.ENERGY` | `LazyOptional` + `CapabilityEnergy` | `ForgeCapabilities.ENERGY` |
| 工具提示 | `addInformation` | `appendHoverText` | `appendHoverText` |
| 物品模型 | JSON + `ModelLoader` | JSON + BEWLR | JSON + `ItemRenderer` |
| 声音/粒子 | `world.playSound` | `level.playSound` | `level.playSound` |
| 事件总线 | 单总线 | 双总线 | 双总线（MOD/FORGE） |
| `IUpgrade.applyUpgrades` | `NBTTagCompound` | `CompoundTag` | `CompoundTag` |
| `IUpgradeableTool.recalculateUpgrades` | `(ItemStack)` | `(ItemStack, Level, Player)` | `(ItemStack, Level, Player)` |
| IE 手册 | `ManualHelper.addEntry` | 数据驱动 | 数据驱动（`assets/ie/manual/*.json`） |

## 3. 多版本工程结构（推荐）

```
IEAddon/
├─ common/                     ← 共享：lang、贴图、设计文档、配方表（非代码）
├─ versions/
│  ├─ 1.20.1/                  ← Forge 47.3.0 + FG6 + Java 17
│  │  ├─ build.gradle
│  │  ├─ gradle.properties
│  │  └─ src/main/java/...
│  └─ 1.12.2/                  ← Forge 14.23.5.2859 + FG2.3 + Java 8
│     ├─ build.gradle
│     └─ src/main/java/...
├─ libs/                       ← IE jar（编译用，不进发布包）
└─ docs/                       ← 本地文档库
```

**原则**：
- Java 源码**不共享**（包名、类名、方法签名全变）。
- 资源可共享：`lang/*.json` 的 key 若按 `item.<modid>.<name>` 统一命名，可整份复用；
  贴图 png 直接复用；模型 JSON 结构两版基本一致（`parent: item/generated`）。
- 配方 JSON 的格式在 1.12.2 与 1.20.1 之间**不同**（1.12.2 是 `"type": "minecraft:crafting_shaped"` + `"item"`；1.20.1 用 `"item"` 字段但 tag 语法变了），需要各自维护。

## 4. 从 1.20.1 移植到 1.12.2 的映射速查

| 1.20.1 | 1.12.2 |
|---|---|
| `stack.getOrCreateTag()` | `stack.getOrCreateSubCompound("mymod")` |
| `CompoundTag.putInt` | `NBTTagCompound.setInteger` |
| `stack.getCapability(ForgeCapabilities.ENERGY)` | `stack.getCapability(CapabilityEnergy.ENERGY, null)` |
| `Item.Properties().stacksTo(1)` | `new Item().setMaxStackSize(1)` |
| `Component.translatable("key")` | `I18n.translateToLocal("key")` |
| `level.isClientSide()` | `world.isRemote` |
| `player.getMainHandItem()` | `player.getHeldItemMainhand()` |
| `RegistryObject<Item>` | `Item` 直接持有 |
| `DeferredRegister.Items` | `RegistryEvent.Register<Item>` |
| `@Mod.EventBusSubscriber(bus = Bus.FORGE)` | `@Mod.EventBusSubscriber`（唯一总线） |

## 5. 版本选择建议（针对"工具/装备 addon"）

1. **只想快速出成果**：做 1.20.1。工具链现代、IE API 完整（`src/api` 223 类）、参考 addon 多。
2. **想覆盖最多老整合包**：补 1.12.2。但 FG 2.3 配置脆、JDK 8 必需。
3. **想长期维护**：1.20.1 + 1.21.1 双 NeoForge 工程，共享资源。
4. **不建议**：1.16.5 / 1.18.2 / 1.19.2 单独开坑——玩家基数小，维护成本高，除非你的目标整合包锁定在这些版本。

## 6. 一个必须接受的现实

IE 的 API 在每个大版本都**重写**（不是改包名，是改设计）：
- 1.12.2 的 `IUpgrade` 用 `NBTTagCompound`；
- 1.16.5 起换 `CompoundTag`；
- 1.20.1 的 `IUpgradeableTool` 增加了 `Level`/`Player` 参数；
- 1.21.1 又迁到 NeoForge 的 `DataComponent`（物品数据组件）体系。

所以"1.12.2 往上全兼容"在代码层面**不存在**，只能"一套设计、多套实现"。
你的工程骨架就是按这个前提搭的。
