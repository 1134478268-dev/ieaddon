# 09 · IE 多方块结构与自动搭建器

## 1. 两套完全不同的实现

| | 1.20.1（10.x） | 1.12.2（0.12.x） |
|---|---|---|
| 结构来源 | `data/immersiveengineering/structures/multiblocks/*.nbt` | 代码里的 `ItemStack[][][]` |
| 基类 | `TemplateMultiblock`（`api/multiblocks/`） | 直接实现 `MultiblockHandler.IMultiblock` |
| 结构 API | `List<StructureBlockInfo> getStructure(Level)` | `ItemStack[][][] getStructureManual()` |
| 朝向 | `MultiblockOrientation(front, mirrored)` | `EnumFacing` + `boolean mirrored` |
| 模板数量 | 22 个 `.nbt` | 每个多方块类各写一份三维数组 |

**这对自动搭建工具是决定性差异**：

- 1.20.1 能拿到**方块状态**（`BlockState` + NBT），可以直接摆；
- 1.12.2 只能拿到**物品**（`ItemStack`），要自己 `ItemStack → BlockState` 推导，
  而且 IE 的很多多方块部件（如 `blockSheetmetal` 的变体）需要额外判断。

所以先做 1.20.1，1.12.2 的移植放在后面（见第 7 节）。

`.nbt` 是原版结构模板格式（`StructureTemplate`），包含调色板（palette）和方块列表。

### 2.2 `TemplateMultiblock` 的关键成员

```java
public abstract class TemplateMultiblock implements IMultiblock {
    protected final BlockPos masterFromOrigin;   // 主方块在模板里的位置
    protected final BlockPos triggerFromOrigin;  // 触发方块在模板里的位置
    protected final BlockPos size;               // 结构尺寸

    public List<StructureBlockInfo> getStructure(Level world); // 不含空气
    public Vec3i getSize(Level world);
    public boolean canBeMirrored();
    public BlockPos getMasterFromOriginOffset();
    public BlockPos getTriggerOffset();          // 来自 IMultiblock

    // 坐标变换：把"模板相对坐标"变成"按朝向/镜像旋转后的相对坐标"
    public static BlockPos getAbsoluteOffset(BlockPos relative, boolean mirrored, Direction facing);
    public static BlockPos withSettingsAndOffset(BlockPos origin, BlockPos relative, Mirror, Rotation);
}
```

`StructureBlockInfo` 是原版类，三个字段：

```java
record StructureBlockInfo(BlockPos pos, BlockState state, @Nullable CompoundTag nbt)
```

**`pos` 是相对模板原点的坐标**（原点 = 模板最小角，不是主方块）。

## 3. IE 是怎么"成型"的（`createStructure` 逐行拆解）

`TemplateMultiblock#createStructure` 是自动搭建工具的算法蓝本：

```java
Rotation rot = DirectionUtils.getRotationBetweenFacings(Direction.NORTH, side.getOpposite());
// side 是玩家点击的面；点击面的反方向 = 结构正面

for (Mirror mirror : getPossibleMirrorStates()) {
    StructurePlaceSettings placeSet = new StructurePlaceSettings().setMirror(mirror).setRotation(rot);

    // 关键：由"点击位置"反推模板原点
    BlockPos origin = pos.subtract(
        StructureTemplate.calculateRelativePosition(placeSet, triggerFromOrigin));

    for (StructureBlockInfo info : getStructure(world)) {
        BlockPos here = origin.offset(
            StructureTemplate.calculateRelativePosition(placeSet, info.pos()));
        BlockState expected = info.state().mirror(mirror).rotate(rot);

        if (!BlockMatcher.matches(expected, world.getBlockState(here), ...).isAllow())
            continue mirrorLoop;   // 这个朝向/镜像不成立，试下一个
    }
    // 全部匹配 → 成型
    if (!world.isClientSide)
        form(world, origin, rot, mirror, side);
    return true;
}
```

三个要点：

1. **原点不是点击位置**。点击的是触发方块，要先减去触发方块在模板里的相对坐标。
2. **旋转和镜像同时作用**：`state.mirror(mirror).rotate(rot)`。
3. **形成（form）不是简单放方块**：`replaceStructureBlock` 会把普通方块替换成
   多方块部件（master / dummy），并写方块实体数据。

## 4. 自动搭建器的设计

### 4.0 先解决：玩家到底要摆哪个结构？

这是整个工具最关键的产品问题。IE 没有"JEI 结构预览"，玩家和工具都不能靠猜。

我用脚本解析了 22 个 `.nbt` 模板里触发方块位置的实际方块，结果很反直觉：

| 结构 | 触发方块 |
|---|---|
| 电弧炉 `arcfurnace` | **`minecraft:cauldron`（炼药锅）** |
| 粉碎机 `crusher` | **`immersiveengineering:steel_fence`（钢栅栏）** |
| 金属冲压机 `metal_press` | **`minecraft:piston`（活塞）** |
| 装配机 `assembler` | **`immersiveengineering:conveyor_basic`（基础传送带）** |
| 柴油发电机 `diesel_generator` | **`immersiveengineering:generator`（发电机）** |
| 混合器 `mixer` | `immersiveengineering:sheetmetal_iron`（铁板金属） |
| 炼油厂 `refinery` | `immersiveengineering:heavy_engineering`（重型工程块） |
| 避雷针 `lightning_rod` | `immersiveengineering:light_engineering`（轻型工程块） |
| 焦炉 `coke_oven` | `immersiveengineering:cokebrick`（焦炉砖） |
| 高炉 `blast_furnace` | `immersiveengineering:blastbrick`（高炉砖） |

两个致命事实：

1. **触发方块不唯一**：`heavy_engineering`、`light_engineering`、`sheetmetal_iron`
   这类建材被多个结构共用，`isBlockTrigger` 会同时匹配好几个结构。
2. **触发方块反直觉**：谁能想到电弧炉要放炼药锅、冲压机要放活塞？
   玩家不可能记住 22 个触发方块，工具也不该要求他记。

所以"右击触发方块自动猜结构"只能当**辅助模式**，不能当主方案。必须引入显式选择。

三种选择机制的对比：

| 方案 | 玩家体验 | 实现成本 | 问题 |
|---|---|---|---|
| **核心方块（触发方块）** | 拿对应方块点一下即可 | **低** | 4 组结构共用核心方块 |
| 结构选择器 GUI | 直观，能看列表 | 中（Screen + 网络包） | GUI 代码量大 |
| 蓝图物品 | 拿哪张图建哪个 | 低 | 多一个中间物品，玩家嫌麻烦 |

**选核心方块**，理由：

- 玩家不需要额外物品，符合"拿方块 → 点一下 → 建好"的直觉；
- 核心方块本身就是配方材料的一部分，天然自洽；
- 只有 4 组共享（见下表），用"最小优先 + 预放标志方块"就能解决；
- 蓝图物品被否决：合成蓝图再拿蓝图去建，确实是多此一举。

### 4.0.1 共享核心方块的处理

22 个结构里有 4 组共用同一个核心方块：

| 核心方块 | 结构 |
|---|---|
| `sheetmetal_iron`（铁板金属） | 混合器、锯木机、储罐、筒仓 |
| `cauldron`（炼药锅） | 电弧炉、发酵桶 |
| `conveyor_basic`（基础传送带） | 装配机、灌装机 |
| `heavy_engineering`（重型工程块） | 挖掘机、炼油厂 |

工具的处理：

1. 收集所有以该方块为核心、且**能放得下**的结构；
2. 排序规则：**"周围已经就位的方块数"降序**，相同时保持 IE 的注册顺序
   （和工程师手册的排列一致）；
3. 聊天栏提示"该核心方块可用于 N 个结构，已选择：XX"；
4. 想建另一个，**先在原地放一个该结构特有的方块**（例如锯木机的锯片）。
   这会直接提高该结构的"已就位方块数"，下一轮排序它就会胜出——不需要任何 UI。

> 为什么不用"最小优先"：`cauldron` 同时对应电弧炉（5×5×5）和发酵桶（更小），
> 只按尺寸会永远建出发酵桶。改成"已匹配方块数 + 注册顺序"后，
> 电弧炉在 IE 里先注册，默认就是电弧炉；玩家放个电极也能直接锁定它。

### 4.1 核心取舍：只摆方块，成型交给 IE

```
玩家右击触发方块
   → 遍历 MultiblockHandler.getMultiblocks()
   → isBlockTrigger(点击的方块状态, 点击面) 筛选
   → 用 createStructure 的同一套坐标算法算出每个位置
   → 检查每个位置：已是正确方块 / 可替换 / 被挡住
   → 统计材料 → 扣背包 → setBlock
   → 调 multiblock.createStructure(...) 让 IE 自己成型
```

**为什么不自己直接生成 master/dummy？**
IE 的 `form()` 里每个多方块有自己的 `replaceStructureBlock` 逻辑，
还涉及 `MultiblockFormEvent`、方块实体初始化、部件朝向。绕过它必然出 bug，
而且升级 IE 版本就崩。让 IE 自己成型是唯一稳的做法。

### 4.2 材料统计的坑

- `BlockState.getBlock().asItem()` 对大多数方块有效；
- 但对**多方块部件**（`MultiblockPartBlock`）返回的是 `MultiblockItem`，
  而模板里存的是"成型前"的普通方块，所以这里拿到的也是普通物品，正确；
- `asItem() == Items.AIR` 的方块（如技术性方块）不计入材料；
- 潜行右击只预览不扣材料，方便玩家先看清单。

### 4.3 已实现的代码

`versions/1.20.1/src/main/java/com/ieaddon/template/item/MultiblockBuilderItem.java`

| 方法 | 作用 |
|---|---|
| `useOn` | 入口：找结构 → 预览 / 检查材料 / 建造 |
| `findPlans` | 遍历 `IMultiblock`，用 `isBlockTrigger` 筛选，返回**所有**能放下的方案 |
| `execute` | 逐格 `setBlock`（含 NBT），最后调 `createStructure` 成型 |
| `missing` | 返回"还差多少"，用于精确提示 |
| `consume` | 扣背包材料（创造模式跳过） |

使用方式：

```
合成：2 铁锭 + 1 木棍（无序）
右击焦炉砖        → 自动摆出 3x3x3 焦炉并成型
潜行 + 右击       → 只在聊天栏显示材料清单
材料不够          → "材料不足，还缺 15x 焦炉砖、3x 重型工程块"
```

### 4.5 第二个入口：工程师手册 Shift + 右键

不需要额外物品，拿着 IE 自带的工程师手册，**Shift + 右键多方块核心方块**即可搭建。

为什么原版没有冲突（源码依据，1.20.1 `ManualItem`）：

```java
@Override
public InteractionResultHolder<ItemStack> use(Level world, Player player, InteractionHand hand) {
    if (world.isClientSide)
        ImmersiveEngineering.proxy.openManual();   // 直接开 GUI，不看 Shift
    return new InteractionResultHolder<>(InteractionResult.SUCCESS, player.getItemInHand(hand));
}

@Override
public InteractionResult useOn(UseOnContext context) {
    // 只有右键讲台才做事（放书），其余返回 PASS
    if (blockstate.getBlock() instanceof LecternBlock)
        return LecternBlock.tryPlaceBook(...) ? InteractionResult.SUCCESS : InteractionResult.PASS;
    return InteractionResult.PASS;
}
```

结论：**Shift + 右键在 IE 里和普通右键完全等价**，拦截它不破坏任何功能。

实现（`event/ManualBuildHandler.java`）：

```java
@SubscribeEvent
public static void onRightClickBlock(PlayerInteractEvent.RightClickBlock event) {
    if (!event.getEntity().isShiftKeyDown()) return;
    if (!isEngineersManual(event.getItemStack())) return;
    if (event.getLevel().getBlockState(event.getPos()).getBlock() instanceof LecternBlock) return; // 放行放书

    event.setCanceled(true);
    event.setCancellationResult(InteractionResult.SUCCESS); // 客户端不再打开手册
    if (!event.getLevel().isClientSide)
        MultiblockBuilderItem.tryBuild(event.getLevel(), event.getEntity(), event.getPos(), event.getFace(), false);
}
```

三个细节：

1. **判断手册用注册名** `immersiveengineering:manual`，不 import IE 的 `IEItems.MANUAL`，
   避免依赖 internal 包；
2. **右键讲台放行**，保留"把手册放上书架"的原版行为；
3. `RightClickBlock` 在 `useOn` / `use` 之前触发，cancel 后客户端不会弹手册。

### 4.6 两个入口对照

| 入口 | 操作 | 行为 |
|---|---|---|
| **工程师手册** | Shift + 右键方块 | 直接搭建（零额外物品） |
| 自动搭建器 | 右键方块 | 直接搭建 |
| 自动搭建器 | 潜行 + 右键 | 预览材料，不建造 |

限制：

- 只支持**点击核心方块**（和 IE 锤子一致）；点其他方块会提示失败；
- 不处理"已有部分方块但方向不对"的修复（会判定被挡住）；
- 没有客户端幽灵预览（需要同步模板到客户端，见 6.1）。

## 6. 后续可扩展的方向

### 6.1 客户端幽灵预览

IE 的锤子右击时会渲染半透明预览，原理是 `ClientMultiblocks` + 模板同步：

- 服务端把 `StructureTemplate` 通过自定义包发给客户端，存进
  `TemplateMultiblock.SYNCED_CLIENT_TEMPLATES`；
- 客户端用 `MultiBufferSource` 逐格画 `BlockRenderDispatcher.renderSingleBlock`。

要做的话需要：`SimpleChannel` 网络包 + `RenderLevelStageEvent` 渲染。

### 6.2 撤销

搭建时记录 `List<BlockPos>` 和原方块，给工具加"撤销上一次"模式（潜行 + 滚轮切换）。

### 6.3 材料替代

IE 的多方块允许用矿物词典/标签替代（`BlockMatcher` + `additionalPredicates`），
自动搭建器可以读取 `BlockMatcher` 的匹配结果，支持"用任意铜块代替"。

### 6.4 1.12.2 移植

1.12.2 没有 `StructureBlockInfo`，只有 `ItemStack[][][] getStructureManual()`：

```java
ItemStack[][][] structure = multiblock.getStructureManual();
// 索引是 [y][x][z] 或 [x][y][z]，要按具体实现确认
for (int y = 0; y < structure.length; y++)
  for (int x = 0; x < structure[y].length; x++)
    for (int z = 0; z < structure[y][x].length; z++) {
        ItemStack stack = structure[y][x][z];
        if (stack.isEmpty()) continue;
        BlockState state = Block.getBlockFromItem(stack.getItem())
                .getStateFromMeta(stack.getMetadata());
        // 坐标变换用 MultiblockHandler 的旋转矩阵（1.12.2 是手写的 rotX/rotZ）
    }
```

1.12.2 的 `createStructure` 内部用 `TemplateMultiblock` 不存在，
坐标旋转在 `MultiblockHandler` 或各多方块类里手写，需要单独对照。

## 7. 一句话总结

> IE 的多方块 = **NBT 模板（1.20.1）/ 物品三维数组（1.12.2）** + **统一的
> `isBlockTrigger` / `createStructure` 协议**。
> 自动搭建器只要复刻 `createStructure` 的坐标算法，把方块摆好，最后调一次
> `createStructure`，成型、事件、部件转换全部交给 IE。
