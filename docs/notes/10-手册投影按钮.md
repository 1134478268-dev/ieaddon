# 10 · 工程师手册里的"投影"按钮

## 1. 交互

```
打开工程师手册 → 翻到某个多方块页（例如"焦炉"）
右上角出现 [投影] 按钮
点击 → 关闭手册，投影开始"跟随准星"
移动视角 → 投影跟着准星走（准星命中的方块 = 结构的触发方块，正面朝你）
右键 → 固定投影（这一刻才通知服务端）
左键 → 取消
固定后按线框轮廓放方块
每放对一格，那一格的线框消失
全部放齐 → 自动调用 createStructure 成型
```

不额外加物品，不改原版手册的右键行为。

### 1.1 放置阶段状态机

```
       点 [投影]
          │
          ▼
   PLACING（纯客户端）
   ├─ 每 tick 用 minecraft.hitResult 重算位置
   ├─ 左键 → 清空，回到普通状态
   └─ 右键 → 发包给服务端，进入 ACTIVE
          │
          ▼
   ACTIVE（客户端 + 服务端都有）
   ├─ 玩家放方块 → 服务端检测 EntityPlaceEvent
   ├─ 全部就位 → 服务端 createStructure，客户端 clear
   ├─ 玩家离开投影 15 格 → 客户端和服务端都清理
   └─ 玩家退出 → 服务端静默清理
```

**PLACING 阶段完全不打扰服务端**，只有右键固定时才发一个包。

### 1.2 15 格自动清理

投影固定后，玩家离开投影 15 格，投影自动消失：

- **服务端**：`PlayerTickEvent` 每 tick 检查 `player.blockPosition().distSqr(origin)`，
  超过 `15²` 就移除状态并给玩家一条 action bar 提示；
- **客户端**：`ProjectionRenderer` 的 tick 里做同样的检查，直接 `ClientProjection.clear()`。

距离用 `origin`（模板最小角）算。对 5×5×5 的结构，origin 到中心只有 2.5 格误差，
15 格阈值足够宽松。

这么做的目的：防止投影变成一个"免费的远程结构预览"——玩家必须待在建造现场。

## 2. 为什么不用 Mixin

IE 的手册是 `ManualScreen`（`blusunrize.lib.manual.gui`）。要加按钮有两种做法：

| 做法 | 成本 | 风险 |
|---|---|---|
| Mixin 注入 `ManualScreen.render` | 高（要搭 Mixin 环境） | 跟着 IE 版本改 |
| **Forge ScreenEvent** | 低 | 无 |

选 ScreenEvent：

- `ScreenEvent.Render.Post`：在手册画完之后补画按钮；
- `ScreenEvent.MouseButtonPressed.Pre`：点击时先于手册处理，命中按钮就 cancel。

## 3. 怎么识别"当前页是多方块页"

这是整个功能的关键。IE 没有给 addon 留钩子，但三个信息恰好可访问：

```java
// ManualScreen 里：
public int page;                                  // ✅ public
public ManualEntry getCurrentPage();              // ✅ public

// ManualEntry 里：
public Int2ObjectMap<SpecialManualElement> getSpecialsByPage();   // ✅ public

// ManualElementMultiblock 里：
private final IMultiblock multiblock;             // ❌ private，只能反射
```

所以：

```java
ManualEntry entry = screen.getCurrentPage();
SpecialManualElement special = entry.getSpecialsByPage().get(screen.page);
if (special instanceof ManualElementMultiblock) {
    Field f = ManualElementMultiblock.class.getDeclaredField("multiblock");
    f.setAccessible(true);
    IMultiblock mb = (IMultiblock) f.get(special);
}
```

反射失败就返回 null，按钮不显示——不会影响原版手册。

> 这是"用 IE 内部实现"的典型场景。按许可证，本项目已经开源可见，合规；
> 但 IE 若改字段名，这里会静默失效（按钮消失），不会崩游戏。

## 4. 数据结构

### 4.1 `ProjectionData`（两端共用）

```java
public final class ProjectionData {
    private final IMultiblock multiblock;
    private final BlockPos origin;
    private final Rotation rotation;
    private final Mirror mirror;
    private final Direction face;
    private final List<BlockPos> positions;    // 绝对坐标
    private final List<BlockState> expected;   // 对应期望状态

    public boolean contains(BlockPos pos);
    public int remaining(Level level);         // 还没放对的格数
    public boolean isComplete(Level level);
    public void form(Level level, Player player);  // 交给 createStructure
}
```

由 `IMultiblock.getStructure(level)` + `StructureTemplate.calculateRelativePosition` 计算，
和 `createStructure` 用的是同一套坐标算法。

### 4.2 服务端 `ProjectionManager`

`Map<UUID, ProjectionData>`，每个玩家最多一个。

- `create`：接收请求，若结构已完整直接成型，否则记录并提示"还差 N 格"；
- `onBlockPlaced`：`EntityPlaceEvent` 里判断位置是否属于投影，放齐就 `form` 并移除；
- `remove`：玩家退出时静默清理；
- `clear`：服务器停止时清空。

### 4.3 客户端 `ClientProjection`

三段状态：

```java
@Nullable IMultiblock placing;    // PLACING 阶段的目标结构
@Nullable ProjectionData pending; // 跟随准星的临时投影（每 tick 重算）
@Nullable ProjectionData active;  // 已固定的投影
```

跟随算法和 `createStructure` 一致：把准星命中的方块当作"触发方块"，
用 `triggerOffset` 反推模板原点：

```java
BlockPos origin = hit.getBlockPos()
    .subtract(StructureTemplate.calculateRelativePosition(settings, multiblock.getTriggerOffset()));
```

所以投影的位置就是"如果现在用锤子点这个方块，机器会建在哪"——完全可预测。

## 5. 网络

只有一个包：`ProjectionRequestPacket`（C→S）。

```java
record ProjectionRequestPacket(
    ResourceLocation structure,  // 结构 id
    BlockPos origin,             // 模板原点
    byte rotation, byte mirror, byte face
)
```

服务端收到后 `MultiblockHandler.getByUniqueName` → `ProjectionData.create` → 记录。

**为什么不需要 S→C**：投影的几何数据客户端本来就能算（IE 会把模板同步给客户端用于手册渲染），
所以客户端点按钮时自己 `ProjectionData.create` 一份用于画线框即可。

## 6. 放置检测

```java
@SubscribeEvent
public static void onBlockPlaced(BlockEvent.EntityPlaceEvent event) {
    if (event.getLevel().isClientSide()) return;
    if (!(event.getEntity() instanceof ServerPlayer player)) return;
    ProjectionManager.onBlockPlaced(player, event.getPos());
}
```

`onBlockPlaced` 里：

```java
if (!data.contains(pos)) return;
if (data.isComplete(level)) {
    data.form(level, player);      // multiblock.createStructure(...)
    PROJECTIONS.remove(player.getUUID());
}
```

## 7. 渲染

```java
@SubscribeEvent
public static void onRenderLevel(RenderLevelStageEvent event) {
    if (event.getStage() != Stage.AFTER_TRANSLUCENT_BLOCKS) return;
    // 遍历 positions，已就位的不画，其余的 renderLineBox 绿色线框
}
```

用线框而不是半透明方块：

- 不用处理 `RenderType.translucent()` 的 alpha 排序；
- 不和方块光照/遮挡打架；
- 玩家能透过线框看清里面已经放了什么。

## 8. 限制

1. **投影固定在创建位置**，不跟随玩家。位置不对就再点一次按钮。
2. **换维度不清理**：`ClientProjection` 是静态字段，投影会在新维度继续画（用同样坐标）。
   修法是给 `ProjectionData` 加维度字段，渲染时比对。
3. **只识别"放对位置"**，不识别"放错位置"的回滚。放错只会让那格一直亮着。
4. **反射依赖字段名** `multiblock`，IE 改名就失效（按钮消失，不崩）。
5. **代码未编译验证**——首次构建仍卡在 ForgeGradle 直连官方 maven 的网络问题。

## 9. 与"手册 Shift+右键"的关系

两个入口并存，互不影响：

| 入口 | 操作 | 行为 |
|---|---|---|
| 手册多方块页 | 点 [投影] 按钮 | 生成投影，玩家手动放 |
| 手册任意位置 | Shift + 右键核心方块 | 直接一键搭建（自动扣材料） |

如果之后只想保留投影模式，把 `ManualBuildHandler` 里对
`MultiblockBuildHelper.tryBuild(..., false)` 的调用去掉即可。
