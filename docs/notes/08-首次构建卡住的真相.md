# 08 · 首次构建卡住的真相与三种解法

## 现象

`gradlew compileJava` 停在 `Daemon will be stopped at the end of the build`，
日志不再前进，`jstack` 显示主线程卡在 `SocketDispatcher.read0`（等 HTTP 响应体）。

## 根因

**ForgeGradle 6 内部硬编码了 `https://maven.minecraftforge.net`**，
用来下载 `mcp_config`、`forge-*-universal.jar`、`client.jar`、`server.jar`。
这段下载：

- 不经过你在 `repositories {}` 里配置的 BMCLAPI 镜像；
- 不受 `--offline` 影响（它不用 Gradle 的下载器）；
- 实测速度约 **4 KB/s**（BMCLAPI 同一文件约 1.3 MB/s，差 300 倍）。

所以「配置了镜像 + 调大超时」最多让它不报错，但会慢到不可用。

## 三种解法（按推荐顺序）

### 方案 A：给 Gradle 配代理（最快）

`gradle.properties` 里取消这两组注释，改成你代理的端口：

```properties
systemProp.https.proxyHost=127.0.0.1
systemProp.https.proxyPort=7890
systemProp.http.proxyHost=127.0.0.1
systemProp.http.proxyPort=7890
```

然后：

```powershell
$env:JAVA_HOME='D:\dev\tools\jdk-17'
$env:GRADLE_USER_HOME='D:\dev\tools\gradle-home'
cd D:\dev\projects\IEAddon\versions\1.20.1
.\gradlew.bat build
```

首次构建约 5~15 分钟（取决于网速），之后走缓存秒开。

### 方案 B：借一台能联网的机器构建一次，拷贝缓存

在任意能正常访问 `maven.minecraftforge.net` 的机器上，用同样的工程跑一次：

```powershell
$env:GRADLE_USER_HOME='D:\dev\tools\gradle-home'
.\gradlew.bat build
```

然后把整个 `D:\dev\tools\gradle-home` 目录（约 1~2 GB）拷到本机同路径。
之后本机可 `--offline` 构建。

> 注意：路径必须一致，`GRADLE_USER_HOME` 不能变。

### 方案 C：改用 1.12.2 / 1.16.5（ForgeGradle 2.3 / 5）

老版本 ForgeGradle 对 BMCLAPI 的兼容性更好，但同样要下载 MC，
只是没有 6.x 那层硬编码。成功率略高，不是根本解法。

## 怎么确认卡住而不是在编译

```powershell
# 看主线程栈
& 'D:\dev\tools\jdk-17\bin\jstack.exe' <java pid> | Select-String '"Daemon worker"' -Context 0,6
```

- 栈里有 `SocketDispatcher.read0` → 在等网络；
- 栈里有 `javac` / `JavacTask` → 在真编译（正常，等即可）；
- 缓存目录 `D:\dev\tools\gradle-home` 大小持续增长 → 在下载。

## 已经做过的优化（保留在工程里）

| 优化 | 位置 |
|---|---|
| Gradle 发行版本地镜像（腾讯云，5 MB/s） | `gradle/wrapper/gradle-wrapper.properties` |
| 依赖仓库走 BMCLAPI | `settings.gradle` + `build.gradle` |
| FG 插件固定版本 `6.0.24`（避免 metadata 查询超时） | `build.gradle` |
| HTTP 超时调到 180s | `gradle.properties` |
| IE 依赖用 `flatDir` + `fg.deobf(坐标)`（`files()` 无法 deobf） | `build.gradle` |

## 一个必须知道的事实

`fg.deobf(files(...))` **不工作**，ForgeGradle 会打印：

```
files(...) dependencies are not deobfuscated. Use a flatDir repository instead
Cannot deobfuscate dependency of type DefaultSelfResolvingDependency_Decorated
```

必须用：

```groovy
repositories { flatDir { dirs "../../libs" } }
dependencies { compileOnly fg.deobf("blusunrize.immersiveengineering:ImmersiveEngineering:10.2.0") }
```

并且 jar 文件名必须是 `ImmersiveEngineering-10.2.0.jar`（`<artifact>-<version>.jar`）。
工程里已经这样配置好了。
